案情

接續上午那台被巨集文件打進來的財會部主機。EDR 告警後，你已經用 System Informer 看過行程樹，確認執行鏈是 OUTLOOK → WINWORD → powershell → 假 svchost → rundll32，另有兩個被拉出樹外的分支。

但行程只要重開機就沒了。攻擊者要維持存取，就必須在某個「開機或登入時會被自動執行」的地方留下入口——這就是持久化（persistence）。你現在用 Autoruns 掃這台主機，要回答的問題只有一個：重開機之後，這台電腦還會不會自己把惡意程式叫回來？

判斷持久化項目的五個常見警訊

警訊說明
沒有數位簽章正常軟體大多有廠商簽章；Publisher 空白或驗證失敗就要小心
路徑很奇怪藏在 %TEMP%、%APPDATA%、C:\Users\Public、C:\ProgramData
檔名像亂數如 a8f3kx2.exe，或假冒系統程式名稱（svchost32.exe）
沒有描述、沒有公司名稱Description、Publisher 欄位空白
Autoruns 標色提醒粉紅＝無簽章或無描述；黃色＝檔案已不存在

符合越多項，越值得深入調查。但這五項是篩選器，不是判決書——本實驗刻意安排了「五項都不符合卻是惡意」與「符合兩三項卻完全正常」的項目。清查完之後，請回頭檢討這五項各自在哪裡失效。

你的任務

  1. 逐項判讀 22 個自動啟動項目，標記「可疑」或「正常」。
  2. 先在預設狀態（Hide Microsoft entries 勾選）下數一次你找到幾個。取消勾選再數一次。差幾個？為什麼會差？
  3. 有三個項目符合上表的警訊，卻是正常的。分別說明它們為什麼正常。
  4. 用「依 Timestamp 排序」找出寫入時間集中的區段。注意：登錄檔的 Run 機碼底下所有項目共用同一個機碼的最後寫入時間，所以時間只能告訴你「這個機碼被動過」，不能告訴你「是哪一個值被動的」。說明這個限制對你的判斷有什麼影響。
  5. 把找到的持久化項目與上午行程樹裡的檔案對應起來，指出哪些是同一批檔案。
  6. 假設你只能先移除一個項目，你選哪一個？為什麼？移除之後這台機器就乾淨了嗎？
